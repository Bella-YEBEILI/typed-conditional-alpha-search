# QuantaAlpha 框架说明

`quantaalpha` 是 QuantaAlpha 项目的核心 Python 包，负责把“研究想法 -> 假设生成 -> 因子表达式 -> 代码实现 -> 回测评估 -> 反馈迭代”串成一个可持续运行的量化因子挖掘闭环。

它不是单一的回测脚本，也不是单纯的 LLM 包装层，而是一个把研究流程工程化、标准化、可复用化的框架。

## 一句话理解

QuantaAlpha 的目标是把因子研究做成一条自动化流水线：

1. 从方向或语义假设出发
2. 在当前运行时允许的字段和算子约束下生成表达式
3. 生成可执行因子代码
4. 用统一的 TQ 兼容回测引擎计算绩效
5. 用反馈驱动下一轮改进
6. 在需要时继续做 mutation / crossover 演化搜索

## 框架亮点

### 1. 研究闭环完整

框架不是“只会产表达式”，而是完整覆盖：

- 假设生成
- 因子构造
- 代码实现
- 因子值计算
- 回测验证
- 反馈总结
- 轨迹沉淀
- 多轮进化

这意味着每一轮实验都有来源、有结果、有反馈、有后续方向，而不是一次性产物。

### 2. 运行时约束强，减少无效探索

框架会在生成和执行前后持续做约束：

- 字段白名单约束
- 算子白名单约束
- 活跃数据域约束
- 多域覆盖校验
- 表达式可解析性校验
- 重复度、复杂度、一致性检查

这样可以显著减少“写得出来但跑不通”“语义上不对”“跨域漂移”“复杂度过高导致过拟合”的问题。

### 3. 数据域是第一等公民

框架显式支持多种数据域，并且把数据域贯穿到：

- prompt 生成
- 因子表达式约束
- 代码实现检查
- 回测前校验
- 反馈归因
- crossover 语义引导

当前主要域包括：

- `pv`：日频价量
- `fundamental`：基本面
- `minutes`：分钟级数据

当多个域共同启用时，框架要求表达式真实覆盖所有活跃域，而不是只在文字层面“假装混合”。

### 4. 回测链路统一，指标口径清晰

`backtest` 子系统把数据读取、因子值计算、分组收益、RankIC、收益曲线、净收益、换手、覆盖率等指标统一在一套口径下完成。

这带来几个好处：

- 各轮实验可横向比较
- 训练与验证逻辑一致
- 反馈能基于统一指标口径生成
- 后续可以方便补充质量诊断和人工分析

### 5. 反馈不是泛泛点评，而是可行动的研究指导

反馈模块会综合：

- 当前假设
- 实际生成并实现的因子
- 选择阶段关键指标
- 中性化 / 子域变换上下文
- 复杂度问题
- 当前运行时活跃域证据

输出下一轮应该保留什么、删掉什么、简化什么、往哪里继续试，而不是只说“效果一般，建议优化”。

### 6. 支持进化式搜索

除了常规单轮“提假设 -> 做实验”，框架还支持：

- `Original`：原始探索
- `Mutation`：沿父策略做正交变异
- `Crossover`：融合多个父策略的优势

其中 `crossover` 不是简单拼公式，而是先做语义层分析，再把语义引导交给后续假设生成。

### 7. 工程化程度高，适合持续研究

框架内置了：

- 实验配置
- 运行态环境切换
- 轨迹池管理
- 因子库沉淀
- 结果缓存
- 自动日志
- 手工质量分析工具

所以它既适合单次实验，也适合长期研究积累。

## 核心执行链路

主入口通常从 `quantaalpha/cli.py` 或 `quantaalpha/pipeline/factor_mining.py` 开始，核心链路如下：

1. 读取实验配置和环境变量
2. 解析当前运行模式
3. 解析当前活跃数据域
4. 构造 `AlphaAgentLoop`
5. 生成 hypothesis
6. 生成 factor expression
7. 生成 factor code
8. 执行回测
9. 生成 feedback
10. 记录 trajectory / factor library
11. 如启用 evolution，则继续 mutation / crossover

对应模块关系大致是：

- `pipeline` 负责流程编排
- `factors` 负责假设、表达式、校验、反馈、因子库
- `backtest` 负责执行与评估
- `llm` 负责模型调用
- `core` / `components` 负责抽象与可插拔能力

## 目录导读

### `pipeline`

负责主流程控制和进化调度。

关键职责：

- 因子挖掘主入口
- 单轮 loop 调度
- planning 方向拆分
- evolution controller / mutation / crossover
- trajectory 记录与父策略选择

如果你想看“系统是怎么跑起来的”，通常先看这里。

### `factors`

这是量化研究逻辑最集中的模块。

关键职责：

- hypothesis 生成
- expression 生成
- prompt 装配
- 域约束与字段校验
- factor regulator
- factor coder
- feedback 生成
- factor library 沉淀
- TQ runner 对接

如果你想看“因子是怎么被提出、约束、实现、评价的”，这里最关键。

### `backtest`

负责 QuantaAlpha 内置的 TQ 兼容回测链路。

关键职责：

- 运行时数据读取
- 因子值计算
- 收益、换手、覆盖率、分组收益、RankIC 计算
- profile / params 管理
- transform pipeline
- 质量分析与绘图

如果你想看“指标怎么算出来的”，重点看这里。

### `core`

负责框架级抽象。

关键职责：

- 实验抽象
- proposal / feedback 抽象
- 场景抽象
- 基础配置和异常
- 演化框架公共能力

可以把它理解为框架的骨架层。

### `components`

负责通用、可插拔的 proposal / runner / benchmark 组件。

它更偏框架公共积木，不只服务单一因子场景。

### `llm`

负责模型调用封装和配置管理。

这里解决的是：

- 怎么调用模型
- 怎么组织消息
- 怎么解析结构化输出
- 怎么统一模型侧配置

### `utils` / `app` / `log`

属于支撑层：

- `utils`：通用辅助工具
- `app`：运行环境与应用辅助
- `log`：日志与运行观测

## 典型工作流

### 场景一：单轮因子研究

适合快速验证一个方向。

流程：

1. 给出初始方向
2. 生成假设
3. 生成 1~N 个因子表达式
4. 代码实现
5. 回测
6. 根据 feedback 进入下一轮

### 场景二：多方向并行探索

适合把一个大方向拆成多个子方向，平行搜索。

流程：

1. planning 生成多个 directions
2. 每个 direction 独立运行 loop
3. 对比不同方向的表现
4. 筛出更优方向进入下一阶段

### 场景三：进化式搜索

适合在已有较好策略附近继续搜索。

流程：

1. Original 产出初始轨迹
2. Mutation 寻找正交变体
3. Crossover 融合父策略
4. 在轨迹池中持续比较和筛选

## 当前版本特别值得关注的设计点

### 1. Crossover 强调“先语义，后表达式”

新的 crossover 设计不是机械拼接父策略，而是先回答几个问题：

- 每个父策略的 alpha 来源是什么
- 经济学含义是什么
- 两者为什么互补
- 应该用哪种组合结构
- 之后的假设生成应该沿什么语义引导继续

这能减少“公式拼贴感”，让融合更像真实研究。

### 2. 反馈越来越强调“真实证据归因”

反馈不应该凭空脑补域角色，所以框架会尽量把真实证据带进去，比如：

- 当前活跃域
- 模块真实声明字段
- 分钟输入
- 选择阶段关键指标
- 变换和中性化上下文

目标是让反馈更像研究复盘，而不是泛化评论。

### 3. 复杂度控制被放到重要位置

量化因子研究中，一个很常见的问题是：

- 训练期表现很好
- 测试期快速失效

框架把表达式复杂度、基特征数量、冗余度等问题前置，是为了尽量在生成阶段就压制过拟合倾向。

## 适合谁使用

这个框架比较适合：

- 做因子挖掘自动化的人
- 想把研究流程标准化的人
- 想把 LLM 引入量化研究但不希望失控的人
- 需要长期积累因子库、轨迹和反馈的人

## 快速阅读建议

如果你第一次读这个包，建议顺序如下：

1. `cli.py`
2. `pipeline/factor_mining.py`
3. `pipeline/loop.py`
4. `factors/proposal.py`
5. `factors/tq_runner.py`
6. `backtest/bridge.py`
7. `backtest/evaluator.py`
8. `backtest/result_engine.py`
9. `factors/feedback.py`
10. `pipeline/evolution/*`

这样能比较快把主链路串起来。

## 总结

QuantaAlpha 的核心价值不只是“自动生成因子”，而是把量化研究流程变成一个可约束、可回测、可复盘、可进化的系统。

它把研究语义、表达式约束、工程实现、回测评估和反馈迭代连接成了一套完整框架。对长期因子研究来说，这种“流程级能力”往往比单个高分因子更重要。
